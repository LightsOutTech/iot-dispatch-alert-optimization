# 工业物联网告警现场运维防空跑优化方案

## 1. 我的判断（看到了什么、根问题是什么）

### 1.1 数据全景与现状量化
本方案基于全量数据集 `device_alerts.csv`（共 1140 条告警记录，覆盖 5 大厂区、10 类工业终端设备）进行深入分析：
- **已完成核实派单**：1091 条。
  - **有效派单 (`is_valid_dispatch == '1'`)**：955 条（占比 87.53%），现场确需维修。
  - **无效空跑派单 (`is_valid_dispatch == '0'`)**：136 条（占比 12.47%），工程师到场时设备已自行恢复或为偶发瞬态假告警。
- **待核实告警 (`is_valid_dispatch == ''`)**：49 条。
- **基线损失**：按业务核算口径（每次现场空跑损失 90 个单位，暂缓派单复核一次花费 10 个单位），若全部直接派单，基线空跑总损失为：
  $$\text{Baseline Loss} = 136 \times 90 = 12240 \text{ 个单位}$$

### 1.2 根问题定位：边缘网关时钟漂移/上报滞后与瞬态弱信号波动
通过对时间戳、信号及通信重传特征的多维交叉比对，定位出两大根因：

1. **核心根因：网关时钟偏差/数据滞后同步（时钟前漂与瞬态恢复假象）**
   - 将设备事件时间 `event_ts`（网关记录，带 `+08:00` 时区）与平台接收时间 `synced_ts`（云端入库，带 `Z` 零时区）换算至统一 UTC 时间戳后，定义时间偏差：
     $$\Delta t = t_{event} - t_{synced}$$
   - **正常有效派单**的平均 $\Delta t$ 仅为 **12.8 分钟**，且 82.0% 的有效告警 $\Delta t < 15$ 分钟。
   - **无效空跑告警**的平均 $\Delta t$ 高达 **34.8 分钟**：
     - 当 $\Delta t < 15$ 分钟时，误报率仅 **3.6%**（812 单中仅 29 单误报）；
     - 当 $\Delta t \ge 15$ 分钟时，误报率陡增至 **38.4%**（279 单中拦截到 107 单误报，覆盖了全部误报的 78.68%）。
   - **机理剖析**：由于边缘网关与云端 NTP 同步失效，且设备在经历长达数十分钟的离线重试后才将旧快照数据打包补发。当告警在云端触发派单时，现场边缘设备早已自愈脱离异常状态，工程师到场必然扑空。

2. **次要根因：局部厂区边缘信号偶发极弱与高重传瞬态干扰**
   - 深入分析各厂区后发现，东区动力车间、二号焊装厂、南区物流中心、西区涂装车间中，90% 左右的误报均由 $\Delta t \ge 15$ 分钟主导；
   - 而**一号总装厂**的时钟漂移较小，其误报集中由「瞬态弱信号 + 高重试」引起：当信号接收强度 $\text{signal\_dbm} \le 3$ 且 $\text{retry\_count} \ge 25$ 时，由于无线通信突发丢包触发误报，但随后信道恢复使设备状态正常。

## 2. 做了什么（分流拦截与复核策略设计）

针对「空跑损失 90」与「复核成本 10」的高非对称业务成本结构（单次成功拦截净赚 $90 - 10 = 80$ 单位，误判复核仅损耗 10 单位），我们设计了渐进式、强可解释且可在 IoT 规则引擎中毫秒级执行的三套拦截策略：

### 策略对比

1. **策略一（单因子全局时钟偏差拦截，基准白盒策略）**：
   - 规则：$\Delta t \ge 15.0$ 分钟进入暂缓复核流；其余直接派单。
   - 特点：完全基于单变量白盒逻辑，无需设备参数。

2. **策略二（全局双因子协同规则）**：
   - 规则：$\Delta t \ge 15.0$ 分钟，或 $(\text{signal\_dbm} \le 5 \text{ 且 } \text{retry\_count} \ge 70)$ 进入暂缓复核流。
   - 特点：覆盖时钟偏差与重通信拥塞长尾设备。

3. **策略三（厂区自适应分层协同策略，推荐生产部署策略）**：
   - 规则：
     - 若归属 `一号总装厂`：当 $\Delta t \ge 15.0$ 分钟，或 $(\text{signal\_dbm} \le 3 \text{ 且 } \text{retry\_count} \ge 25)$ 时暂缓复核；
     - 其余 4 个厂区：执行 $\Delta t \ge 15.0$ 分钟，或 $(\text{signal\_dbm} \le 5 \text{ 且 } \text{retry\_count} \ge 70)$ 时暂缓复核。
   - 特点：因地制宜，全面消除局部厂区误判，实现全局减损最大化。

## 3. 怎么证明有用（引用由数据算出的数字）

所有数字均由 `solution.py` 在全量发放数据 `device_alerts.csv` 上严格复现计算。

### 3.1 三套策略综合效果横向对比

在 1091 条已完成核实的工单上评估：

| 策略方案 | 核心拦截规则 | 暂缓复核工单数 | 成功拦截空跑数 (召回率) | 漏跑空单 (穿透到场) | 方案总成本 (单位) | 净节省损失 (单位) | 相对减损比例 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Baseline** | 全部直接派单（现状） | 0 (0.00%) | 0 (0.00%) | 136 | 12,240 | 0 | 0.00% |
| **策略 1** | 单因子偏差 ($\Delta t \ge 15\text{m}$) | 279 (25.57%) | 107 (78.68%) | 29 | 5,400 | **+6,840** | **55.88%** |
| **策略 2** | 全局双因子协同规则 | 300 (27.50%) | 110 (80.88%) | 26 | 5,340 | **+6,900** | **56.37%** |
| **策略 3** | **厂区自适应多因子策略 (推荐)** | **318 (29.15%)** | **119 (87.50%)** | **17** | **4,710** | **+7,530** | **61.52%** |

> **核心收益指标**：推荐策略 3 成功拦截了 **87.5%** 的现场空跑派单（从 136 次压缩至仅 17 次漏跑），将无效损失从 **12,240** 单位大幅降低至 **4,710** 单位，净节省 **7,530** 单位，**整体减损达 61.52%**。

## 4. 可复现的脚本与执行步骤

本项目依赖仅使用 Python 3 标准库（无需外部依赖包，开箱即用）。

### 4.1 核心脚本 `solution.py`
脚本完整包含数据解析、统一时区转换、三级策略评估、厂区及设备分解、未标定数据推断。

### 4.2 单元测试 `test_solution.py`
提供 3 个完整的单元测试套件，自动校验所有关键指标的准确性与时钟转换边界。

### 4.3 一键复现命令
在项目根目录下直接运行：
```bash
# 运行端到端评估主程序
python3 solution.py

# 运行自动化单元测试
python3 -m unittest test_solution.py
```
运行将完整打印出上述所有核心指标、分厂区明细及待核实推断结果。
